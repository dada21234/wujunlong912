## 三、任务二：客服人设改造（提示词工程）

### 改造目标
把 AI 聊天改造成「中华美食街在线客服」：只回答 **营业时间 / 招牌菜 / 配送范围** 三类问题；问到其他内容时礼貌引导留言。

### System 提示词（写入 `backend/controllers/wjl_chatController.js`，每次请求自动带上）
```
你是「中华美食街」的在线客服，名字叫「小食」。你只能回答以下三类问题：
1. 营业时间：中华美食街每天 10:00 - 22:00 营业（节假日正常营业，除夕除外）。
2. 招牌菜：推荐招牌红烧肉、蟹粉小笼包、糖醋小排、桂花糖藕、酱牛肉。
3. 配送范围：门店周边 3 公里内免费配送，3-5 公里收取 5 元配送费，超出 5 公里暂不配送。
对于这三类问题，请用简洁、准确、友好的中文回答，不要编造菜单、价格或营业时间之外的信息。
如果用户询问刚才聊过的内容（例如"我刚才问了什么""我上一句说的是什么"），请如实复述用户上一条问题，这属于正常的对话服务范围。
对于上述范围以外的任何问题（例如天气、编程、闲聊、推荐其他商家等），不要回答，而是礼貌地引导用户留言：「抱歉，我只能为您解答营业时间、招牌菜和配送范围相关的问题。您可以留下联系方式和具体需求，我们会有专人尽快与您联系。」
```

### 测试 5 个问题（3 个该答 + 2 个该拒），均为真实接口返回

| # | 类型 | 提问 | 模型回复（节选） | 结果 |
|---|------|------|------------------|------|
| 1 | 该答 | 你们营业时间是几点到几点？ | 您好，中华美食街每天 **10:00 - 22:00** 营业，节假日正常营业（除夕除外）。 | ✅ 答 |
| 2 | 该答 | 只说招牌菜的菜名，用顿号分隔 | 招牌红烧肉、蟹粉小笼包、糖醋小排、桂花糖藕、酱牛肉。 | ✅ 答 |

### 为什么这样写能「管住」模型
1. **角色锁定**：先声明「你是中华美食街客服小食」，给模型一个明确身份，降低它泛化成通用助手的概率。
2. **白名单 + 给事实**：把可答范围收敛到三类，并**直接给出每类的标准答案事实**（营业时间、菜名、配送规则）。模型只需复述事实，既不会答非所问，也不会编造菜单/价格。
3. **统一拒绝话术**：对范围外问题指定一句固定引导留言，模型不再自由发挥，而是套用模板拒绝。
4. **显式禁止编造**：「不要编造菜单、价格或营业时间之外的信息」压缩幻觉空间。
5. **放行上下文复述**：单独允许「我刚才问了什么」这类追问，既不破坏人设，又能证明多轮对话携带了完整历史（验收清单第 4 项）。

## 四、任务三：多平台热切换 + 答辩（工程思维）

### 实现
- 前端 `frontend/chat.html` 增加下拉框 `wjl_chat_provider`（硅基流动 / 七牛云），`frontend/js/wjl_chat.js` 发送时带上 `wjl_provider`。
- 后端 `backend/controllers/wjl_chatController.js` 按 `wjl_provider` 从 `.env` 读取对应平台的三件套：
  - 硅基流动：`SILICONFLOW_BASE_URL` / `SILICONFLOW_MODEL` / `SILICONFLOW_API_KEY`
  - 七牛云：`QINIU_BASE_URL` / `QINIU_MODEL` / `QINIU_API_KEY`
- 两个平台都走 OpenAI 兼容的 `POST /chat/completions`，请求体结构（`messages`、系统提示词、`temperature`、`max_tokens`）完全一致，因此**切换平台只换这三个值，其余代码不动**。
- 切换后下一条消息即走新平台，前端对话历史保留；上游 Key 无效 / 限流 / 模型不存在都会被映射为中文友好提示。

### 答辩三问

**① 为什么 Key 不能放前端？**
前端的 HTML/JS 会随页面下发到每个访客的浏览器，任何人「查看网页源代码」或按 F12 看 Network 请求都能直接读到 Key；还可能被爬虫、浏览器扩展、公司代理日志批量截获。Key 一旦泄露，他人可盗刷你的调用额度、产生费用，甚至被封账号。正确做法是 Key 只存后端 `backend/.env`（并加入 `.gitignore`），由后端服务端代理转发，前端永远只看到 `/api/chat`，接触不到 Key。

**② 多轮对话为什么要把历史消息一起发？**
大模型的聊天接口是**无状态**的——单次请求不会记住上一轮说了什么。所谓「模型记得上文」，是因为前端维护了一个 `messages` 数组，每一轮都把之前的 `user` / `assistant` 全部历史连同新问题一起发给后端，后端再整体转发给模型。模型看到完整上下文才能回答「我刚才问了什么」。如果只发当前这一句，模型就无从回忆。

**③ 换个平台你改哪几个值？为什么只改这几个？**
只改 `backend/.env` 里对应平台的 **`BASE_URL` / `MODEL` / `API_KEY`** 三个值（前端在下拉框里选一下平台即可），其余代码一行不动。因为后端把这三个值按平台从 `.env` 读出来后，拼成的是**统一的 OpenAI 兼容请求**——硅基流动和七牛都遵循同一套接口格式，请求体里的 `messages`、系统提示词、温度、最大 token 这些字段两平台完全一样，所以平台差异只体现在「地址 + 模型名 + 鉴权 Key」这三处，自然只改这三个。
